# DeskBurn 构建流程

本文从空环境开始说明如何测试 Mac 采集端、编译和烧录 ESP32 固件、验证 BLE
链路，以及安装登录自启服务。

## 1. 环境要求

### Mac 侧

- macOS；
- Python 3.10 或更高版本；
- CC Switch；
- Bluetooth 已开启；
- Xcode Command Line Tools，用于跨语言协议测试中的 C++ 编译。

### 固件侧

- PlatformIO Core；
- 支持数据传输的 USB Type-C 线；
- AirM2M CORE ESP32-C3 或按实际硬件修改后的兼容开发板。

检查工具：

```bash
python3 --version
pio --version
c++ --version
```

## 2. 获取代码与安装 Python 依赖

```bash
git clone https://github.com/wnqnxbb/DeskBurn.git
cd DeskBurn

python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/pip install -r requirements.txt
```

`requirements.txt` 只有运行 BLE agent 必需的依赖。正常固件构建不需要安装
`requirements-assets.txt`。

## 3. 运行测试

```bash
cd tools
../.venv/bin/python -m unittest discover -s tests
cd ..
```

测试覆盖：

- Token 与成本聚合；
- SQLite 只读连接；
- 周一、本月和归档边界；
- 跨 `data_source` 去重；
- Python 协议编解码与 CRC；
- 用宿主机 C++ 编译器编译真实 `link_protocol.h`，验证 Python 生成的数据包。

没有 C++ 编译器时，跨语言测试会跳过；开源发布前应在装有编译器的环境再跑一次，
不能把“跳过”当作协议一致性通过。

## 4. 编译固件

正式固件：

```bash
pio run -e deskburn
```

硬件扫描固件：

```bash
pio run -e pin_scanner
```

PlatformIO 会根据 `platformio.ini` 自动安装：

- `espressif32@6.3.0`；
- Arduino ESP32 2.0.9；
- TFT_eSPI 2.5.0；
- NimBLE-Arduino 1.4.x。

这些版本是当前硬件上经过验证的组合。升级 ESP32 core 或 NimBLE 大版本前应单独
建分支验证，尤其不要把 NimBLE 2.x 与 Arduino core 2.x 直接混用。

## 5. 烧录和串口

通常可以让 PlatformIO 自动发现串口：

```bash
pio run -e deskburn -t upload
```

连接多个串口设备时显式指定：

```bash
pio run -e deskburn -t upload \
  --upload-port /dev/cu.usbmodemXXXX
```

查看串口：

```bash
pio device list
pio device monitor --baud 115200
```

ESP32-C3 原生 USB Serial/JTAG 偶尔无法自动进入下载模式。遇到
`No serial data received` 时，按住 `BOOT`、点按 `RST`、松开 `BOOT` 后重试。
更多现象见[踩坑记录](踩坑记录.md#原生-usb-serialjtag-的自动复位不总是可靠)。

## 6. 验证 CC Switch 聚合

默认数据库：

```text
~/.cc-switch/cc-switch.db
```

查看一次聚合结果：

```bash
cd tools
../.venv/bin/python -m ccswitch_agent
```

输出 JSON：

```bash
../.venv/bin/python -m ccswitch_agent --json
```

使用其他数据库文件：

```bash
../.venv/bin/python -m ccswitch_agent --db /path/to/cc-switch.db
```

采集端以 SQLite `mode=ro` 打开数据库，不会写入源文件。

## 7. 验证 BLE

先使用假数据，把数据库问题与 BLE/屏幕问题分开：

```bash
../.venv/bin/python -m ccswitch_agent --serve --fake
```

预期过程：

1. Mac 扫描到广播名 `DeskBurn-<12 位芯片 ID>`；
2. 日志出现 `connected`；
3. 屏幕从 `OFFLINE` 切换为 `LIVE`；
4. 今日金额每 30 秒增加一次；
5. 设备串口出现 `[ble] accepted ...`。

假数据链路正常后，按 `Ctrl-C` 并启动真实数据：

```bash
../.venv/bin/python -m ccswitch_agent --serve
```

macOS 首次运行时可能弹出蓝牙权限提示。授权与 Python 解释器路径有关，因此安装
自启服务时应使用同一个虚拟环境。

固件从 eFuse MAC 自动生成稳定设备名，同一份固件烧到不同板子会得到不同名称。
首次运行且附近只有一台 DeskBurn 时，agent 自动保存绑定：

```text
~/Library/Application Support/DeskBurn/device.json
```

如果附近有多台，agent 会拒绝随便连接。列出并绑定自己的设备：

```bash
../.venv/bin/python -m ccswitch_agent --list-devices
../.venv/bin/python -m ccswitch_agent --bind DeskBurn-70AF0986B648
```

设备名也会由串口打印为 `[ble] advertising as ...`。更换开发板时解除旧绑定：

```bash
../.venv/bin/python -m ccswitch_agent --forget-device
```

绑定保存的是设备自己广播的稳定名称，不是 macOS 为 BLE 外设生成的随机 UUID。

旧版固件固定广播为 `DeskBurn`，旧版 agent 也只查找这个名称；升级到稳定设备 ID
时必须同时更新固件和 agent。两边只升级一边都会扫不到设备，但不会误收数据。

## 8. 安装登录自启

回到仓库根目录，用准备运行服务的 Python 调用安装器：

```bash
cd ..
.venv/bin/python tools/install_launchd.py install
```

安装器会：

- 读取 `tools/launchd/com.deskburn.agent.plist.example`；
- 写入当前 Python、仓库 `tools` 目录和日志的绝对路径；
- 生成 `~/Library/LaunchAgents/com.deskburn.agent.plist`；
- 加载并启动服务。

查看状态：

```bash
cd tools
../.venv/bin/python -m ccswitch_agent --status
```

跟踪日志：

```bash
../.venv/bin/python -m ccswitch_agent --logs
```

卸载：

```bash
cd ..
.venv/bin/python tools/install_launchd.py uninstall
```

卸载不会删除日志。

## 9. 日志轮转

Agent 日志默认位于：

```text
~/Library/Logs/deskburn-agent.log
```

`tools/launchd/deskburn.newsyslog.conf.example` 是可选的 newsyslog 模板。复制前
将最后一行的占位符替换为：

- `__LOG_PATH__`：日志绝对路径；
- `__USER__`：`id -un` 的结果；
- `__GROUP__`：`id -gn` 的结果。

然后安装并验证：

```bash
sudo cp tools/launchd/deskburn.newsyslog.conf.example \
  /etc/newsyslog.d/deskburn.conf
sudo chown root:wheel /etc/newsyslog.d/deskburn.conf
sudo newsyslog -nv /etc/newsyslog.d/deskburn.conf
```

注意：复制前必须真的替换占位符，newsyslog 不会自动展开它们。

## 10. 重新生成 UI 资源

只有修改 `openai.svg`、`claude-color.svg`、中文标签、金额字体或字号时才需要：

```bash
.venv/bin/pip install -r requirements-assets.txt
.venv/bin/python tools/generate_assets.py
pio run -e deskburn
```

生成器依赖 macOS 自带：

```text
/System/Library/Fonts/STHeiti Medium.ttc
/System/Library/Fonts/SFNS.ttf
```

输出文件为 `firmware/deskburn/assets.h`。它是生成产物，不应手工修改。其他操作
系统可以直接使用仓库中已提交的 `assets.h` 编译固件。

## 11. 修改 BLE 协议

线格式有两份实现：

```text
tools/ccswitch_agent/protocol.py
firmware/deskburn/link_protocol.h
```

修改字段时必须同步两边、升级协议版本并运行全部测试。部署时应在同一维护窗口内
完成固件烧录与 Agent 重启；只升级一端会导致设备安全地拒收数据并保持
`OFFLINE`。
